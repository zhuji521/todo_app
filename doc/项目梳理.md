# 待办清单项目梳理

这是一个全栈待办清单。用户可以新增、修改、完成、删除待办，并按状态、关键词、分页查询；每一次操作都会写入历史流水，页面右侧按时间展示。

技术上是 **React 前端 + FastAPI 后端 + MySQL**。开发时前后端分开跑；打包后前端产物放进后端目录，生产环境只开一个 8000 端口。也可以用 Docker Compose 把数据库和接口一起拉起来，数据存在命名卷里。

---

## 1. 它在做什么

页面左边是待办列表，右边是最近 30 条操作历史。

| 用户操作 | 行为 |
| --- | --- |
| 添加 | 内容去掉首尾空格后入库；空内容前后端都会拒绝 |
| 勾选完成 / 取消完成 | 改 `completed`，完成时写入 `completed_at`，取消时清空 |
| 编辑内容 | 只允许未完成的待办修改；已完成时后端返回 409，前端编辑按钮置灰 |
| 删除 | 浏览器二次确认后删除；流水仍保留，可以追溯删过什么 |
| 筛选 / 搜索 / 分页 | 全部、未完成、已完成三个标签；搜索有约 350ms 防抖；每页 10 条 |
| 历史 | 新建、改内容、完成、取消完成、删除都会记一条流水 |

数据存在两张表里：

- `todos`：待办本身（内容、是否完成、创建/更新/完成时间）
- `todo_logs`：操作流水（动作、描述、时间）。删除待办后流水不跟着删

排序规则：未完成排在前面，同一状态里新建的在前。

## 2. 请求是怎么走的

```
浏览器
  │
  ├─ 开发：http://127.0.0.1:5173
  │     Vite 把 /api 代理到 127.0.0.1:8000
  │
  └─ 生产 / Docker：http://<主机>:8000
        FastAPI 同时提供接口和静态页面（同源，不再跨域）
              │
              ▼
        backend/app/routers/todos.py   路由、参数、HTTP 状态码
              │
              ▼
        backend/app/crud.py            业务规则（已完成不能改内容、写流水）
              │
              ▼
        backend/app/models.py          SQLAlchemy 模型
              │
              ▼
        MySQL todo_db（本地 3306；Docker 映射到本机 3307）
        冒烟测试时改用临时 SQLite，不连 MySQL
```

一次「添加待办」的实际路径：

1. `frontend/src/App.tsx` 的 `handleCreate` 调用 `api.create`
2. `frontend/src/api.ts` 发 `POST /api/todos`
3. `backend/app/routers/todos.py` 的 `create_todo` 接收请求
4. `backend/app/schemas.py` 的 `TodoCreate` 校验并裁剪内容
5. `backend/app/crud.py` 的 `create_todo` 写入 `todos`，并记一条 `create` 流水
6. 前端再拉列表、统计和历史

## 4. 主要代码写在哪

业务逻辑集中在三个文件，其余文件是配置、类型、样式或部署。

| 角色 | 文件 | 里面有什么 |
| --- | --- | --- |
| 前端页面与交互 | `frontend/src/App.tsx` | 列表、筛选、搜索防抖、分页、编辑、删除确认、右侧历史、提示条。没有拆成多个组件 |
| 前端接口 | `frontend/src/api.ts` | `fetch` 封装，以及 list / stats / logs / create / updateContent / updateStatus / remove |
| 后端业务 | `backend/app/crud.py` | 建待办、改内容、改状态、删除、分页查询、统计、写流水。已完成不能改内容的规则在这里 |
| 后端接口 | `backend/app/routers/todos.py` | 把上面的函数挂成 HTTP 路由，并把异常转成 404 / 409 |
| 数据表 | `backend/app/models.py` 与 `backend/sql/init.sql` | 同一套表：代码里是 ORM，SQL 文件是手工/容器初始化 |

接口一览（都在 `backend/app/routers/todos.py`，健康检查在 `main.py`）：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| GET | `/api/todos` | 分页列表，参数 `status`、`keyword`、`page`、`page_size` |
| GET | `/api/todos/stats` | 总数 / 未完成 / 已完成 |
| GET | `/api/todos/logs` | 最近操作，`limit` 默认 50，最大 200 |
| POST | `/api/todos` | 新增 |
| PATCH | `/api/todos/{id}/status` | 改完成状态 |
| PATCH | `/api/todos/{id}/content` | 改内容，已完成返回 409 |
| DELETE | `/api/todos/{id}` | 删除 |

## 5. 技术栈，以及各自用在哪些文件

### 前端

| 技术 | 版本（package.json） | 用在哪 | 做什么 |
| --- | --- | --- | --- |
| React 18 | `react` / `react-dom` ^18.3.1 | `frontend/src/main.tsx`、`frontend/src/App.tsx` | `main.tsx` 用 `createRoot` 把应用挂到 `#root`。`App.tsx` 用函数组件和 Hooks（`useState`、`useEffect`、`useCallback`、`useMemo`、`useRef`）管理列表、编辑和提示 |
| TypeScript | ~5.7.3 | `frontend/src/*.ts`、`frontend/src/*.tsx`、`frontend/tsconfig.json`、`frontend/vite-env.d.ts` | 全前端都是 TS。`types.ts` 定义 `Todo`、`TodoLog`、`PageResult`、`Stats`。`tsconfig.json` 开了 `strict`，JSX 用 `react-jsx`。构建脚本先 `tsc --noEmit` 再打包 |
| Vite 6 | ^6.0.7，插件 `@vitejs/plugin-react` | `frontend/vite.config.ts`、`frontend/index.html`、`frontend/package.json` | 开发服务器 `127.0.0.1:5173`，把 `/api` 代理到后端 8000。`index.html` 以模块方式加载 `/src/main.tsx` |
| 原生 CSS | 无 UI 框架 | `frontend/src/styles.css`，由 `main.tsx` 引入 | 布局、列表、标签、历史时间轴、提示条。用 CSS 变量，没有 Tailwind / CSS Modules |
| 浏览器 fetch | 语言内置，无 axios | `frontend/src/api.ts` | 所有接口请求。失败时读后端 `detail` 字段，包成 `ApiError` |

打包相关的关键设置都在 `frontend/vite.config.ts`：

- `base: './'`：资源用相对路径，换部署目录也能打开
- `build.outDir: '../backend/dist'`：产物直接写到后端目录
- `build.assetsDir: 'static'`：得到 `backend/dist/index.html` 和 `backend/dist/static/`

`frontend/src/vite-env.d.ts` 声明了可选环境变量 `VITE_API_BASE`。不设置时 `api.ts` 用相对路径 `/api/...`。

### 后端

| 技术 | 版本（requirements.txt） | 用在哪 | 做什么 |
| --- | --- | --- | --- |
| Python | 本地解释器；镜像是 `python:3.12-slim` | `backend/app/*.py`、`backend/Dockerfile` | 全部后端代码 |
| FastAPI | >=0.115.6 | `backend/app/main.py`、`backend/app/routers/todos.py` | `main.py` 创建应用、挂路由、健康检查、跨域、静态文件。`todos.py` 用 `APIRouter` 声明 REST 接口和查询参数 |
| Uvicorn | >=0.34.0（带 standard） | `backend/Dockerfile` 的 `CMD`，本地用命令启动 | ASGI 服务器，监听 8000。镜像里开了 `--proxy-headers` |
| Pydantic v2 | >=2.10.4 | `backend/app/schemas.py` | 入参 `TodoCreate` / `TodoUpdateContent` / `TodoUpdateStatus`，出参 `TodoOut` / `TodoLogOut` / `PageResult` / `StatsOut`。内容字段会 `strip`，空串报校验错误（HTTP 422） |
| pydantic-settings | >=2.7.0 | `backend/app/config.py` | `Settings` 从环境变量和 `backend/.env` 读配置，拼出数据库 URL |
| SQLAlchemy 2.0 | >=2.0.36 | `backend/app/database.py`、`models.py`、`crud.py` | `database.py` 建引擎和 `SessionLocal`。`models.py` 用 `Mapped` / `mapped_column` 声明表。`crud.py` 用 `select` 做查询、分页和统计 |
| PyMySQL | >=1.1.1 | `backend/app/config.py` 的连接串 `mysql+pymysql://...` | MySQL 驱动。SQLAlchemy 通过它连库，业务代码里不直接 import |
| cryptography | >=44.0.0 | 依赖声明，代码未直接引用 | PyMySQL 连接 MySQL 8 认证时需要 |
| SQLite | Python 标准库 | `backend/smoke_test.py` 通过 `DB_URL=sqlite:///...` | 只用于冒烟测试，让测试不依赖本机 MySQL |
| Starlette TestClient | 随 FastAPI 安装 | `backend/smoke_test.py` | 进程内调用接口，覆盖增删改查、409、分页、SPA 兜底等 |
| logging | Python 标准库 | `backend/app/main.py` | 控制台日志，以及 `backend/logs/app.log`（单文件 5MB，保留 3 个备份） |

分层对应关系：

```
main.py        进程入口、中间件、静态资源
routers/       HTTP 层（路径、状态码）
schemas.py     数据校验层（Pydantic）
crud.py        业务层
models.py      表结构（SQLAlchemy）
database.py    连接与会话
config.py      配置
```

### 数据库

| 技术 | 用在哪 | 做什么 |
| --- | --- | --- |
| MySQL 8.0 | `docker-compose.yml` 的 `mysql` 服务；本地也可自装 | 正式数据存储。字符集 `utf8mb4`，时区 `+08:00` / `Asia/Shanghai` |
| SQL 脚本 | `backend/sql/init.sql` | 建库 `todo_db`、账号 `todo`、表 `todos` 和 `todo_logs`。语句都是 `IF NOT EXISTS`，重复执行不会清数据 |
| SQL 脚本 | `backend/sql/create_database.sql` | 只建库和授权，适合已经有表的环境 |
| Docker 数据卷 `mysql_data` | `docker-compose.yml` | 挂到容器 `/var/lib/mysql`。`docker compose down` 不删数据，`down -v` 才会删 |

表结构以 `backend/sql/init.sql` 为准，ORM 在 `backend/app/models.py` 与之对应。启动时如果 `AUTO_CREATE_TABLES=true`（默认如此），`main.py` 的 lifespan 会再调一次 `Base.metadata.create_all`，已有表不会被改结构。

### 部署与工程配置

| 技术 | 用在哪 | 做什么 |
| --- | --- | --- |
| Docker | `backend/Dockerfile` | 基于 Python 3.12，安装依赖后以 uid 10001 的非 root 用户跑 uvicorn，并带 `/api/health` 健康检查 |
| Docker Compose | `docker-compose.yml` | `todo-mysql`（本机 `127.0.0.1:3307`）和 `todo-api`（`8000`）。API 等 MySQL healthy 后再启动。前端产物以只读卷挂到 `/app/dist`，日志目录挂到 `/app/logs` |
| 环境变量 | 根目录 `.env`、`backend/.env`，示例见对应 `.env.example` | 根目录给 Compose（root 密码、库名、业务账号）。`backend/.env` 给本地 uvicorn（主机、端口、是否自动建表、CORS） |
| 静态托管 | `backend/app/main.py` | 挂载 `/static`；`/` 返回 `index.html`；其他非 `/api` 路径回退到 `index.html`，刷新页面不会 404。未知的 `/api/*` 返回 JSON 404 |

## 6. 本地怎么对上这些文件

开发（两个进程）：

```bash
# 后端，读 backend/.env
cd backend
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

# 前端，vite.config.ts 代理 /api
cd frontend
npm run dev
```

打开 `http://127.0.0.1:5173`。接口文档在 `http://127.0.0.1:8000/docs`（FastAPI 自动生成）。

不连 MySQL 的自检：

```bash
cd backend
python smoke_test.py
```

它会临时改 `DB_URL` 指向 SQLite，再走 `app.main` 里的真实路由。

单端口（先打包再只开后端）：

```bash
cd frontend
npm run build          # 写入 backend/dist
cd ../backend
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

然后访问 `http://127.0.0.1:8000`。

更完整的建库、Docker 和备份命令在 `README.md`。
